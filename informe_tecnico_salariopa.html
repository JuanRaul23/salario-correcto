Visión General del Sistema

SalarioPA es un estimador de salarios para el mercado laboral panameño construido como un sistema ML end-to-end: desde datos reales de mercado hasta una aplicación web que cualquier profesional puede usar. El sistema predice el salario mensual bruto en USD a partir del perfil del usuario, respetando el piso legal establecido por el Decreto N°13 de Mitradel.

Pipeline de Machine Learning

Paso 1 — Agregación por (área, seniority)

Antes de generar registros sintéticos, los 54 cargos se agrupan por (area, seniority) calculando la media de sal_min, sal_max y sal_promedio. Esto resulta en 15 grupos ancla (3 áreas × hasta 5 niveles de seniority).

¿Por qué agregar? Dentro de Finanzas/junior existen 5 cargos con sal_promedio distintos (Cajero $600, Asistente $736, Auxiliar $729…). Si el modelo recibe registros con los mismos features pero salarios distintos, la varianza es irreducible y el MAE no puede bajar de ~$400. Al promediar el grupo, el modelo aprende una sola ancla por combinación y puede ajustar el resto con multiplicadores.

Paso 2 — Generación de dataset sintético

Cada grupo ancla genera 200 registros (120 si es_imputado=1). El salario base sigue una distribución normal muy ajustada: 

# std = 1% del promedio: variación mínima alrededor del ancla real
std = sal_promedio * 0.01
sal_base = RNG.normal(sal_promedio, std)
sal_base = np.clip(sal_base, sal_min * 0.85, sal_max * 1.15)

Para cada registro se samplea aleatoriamente: sector, tipo_empresa, modalidad, provincia, nivel_estudio, nivel_ingles y herramientas, con distribuciones de probabilidad realistas según el área y el nivel de seniority.

Las áreas sin datos reales generan 2,500 registros adicionales desde rangos salariales estimados.

Paso 3 — Multiplicadores de mercado

Cada multiplicador se aplica con un factor de amortiguación D = 0.12 (12% de su efecto declarado), porque el sal_promedio de referencia ya incorpora las condiciones promedio del mercado: 

def m(raw): return 1 + (raw - 1) * 0.12

sal *= m(SECTOR_MUL[sector])    # ej. Banca/Financiero: 1.25 → efecto real: +3%
sal *= m(EMPRESA_MUL[empresa])  # ej. Multinacional: 1.18 → efecto real: +2.2%
sal *= m(ESTUDIO_MUL[estudio])  # ej. Maestría: 1.30 → efecto real: +3.6%
sal *= m(INGLES_MUL[ingles])    # ej. Nativo/Bilingüe: 1.28 → efecto real: +3.4%
sal *= m(MODALIDAD_MUL[mod])    # ej. Remoto: 1.08 → efecto real: +1%
sal *= m(PROVINCIA_MUL[prov])   # ej. Herrera: 0.82 → efecto real: -2.2%
sal *= (1 + bonus_herramientas * 0.12)
sal *= RNG.uniform(0.997, 1.003) # ruido ±0.3%
sal = max(sal, PISO_MITRADEL[area])  # restricción legal

Paso 4 — Años de experiencia (no solapados por seniority)

Clave para que el modelo identifique el nivel salarial con precisión. Los rangos son mutuamente excluyentes:

SeniorityRango años_experienciaMultiplicador salarial implícito
Junior0 – 2 años~0.55× del mid
Mid3 – 6 años1.00× (base)
Senior7 – 11 años~1.80×
Gerencial12 – 17 años~3.50×
Ejecutivo18 – 30 años~7.00×
Por qué es crítico: Con rangos solapados (ej. mid 3-8, senior 6-14), el modelo no puede distinguir un Senior ($3,000) de un Gerente ($7,000) con 12 años. Rangos no solapados → el modelo infiere el nivel con certeza desde años_experiencia y el R² sube de 0.81 a 0.9952.

Modelo de Machine Learning

Algoritmo: GradientBoostingRegressor scikit-learn

Se eligió Gradient Boosting por su robustez con variables categóricas, su capacidad para capturar interacciones no lineales y su buen rendimiento sin requerir grandes volúmenes de datos. Es superior a regresión lineal (no captura interacciones) y a Random Forest (mejor en tabular data con relaciones ordenadas).

HiperparámetroValorJustificación
n_estimators600Más árboles = mejor aproximación a la función multiplicativa
max_depth7Profundidad suficiente para capturar interacciones de 5+ variables
learning_rate0.04Learning rate bajo + muchos árboles = generalización estable
subsample0.8Stochastic boosting: reduce overfitting
min_samples_leaf5Evita hojas con muy pocos puntos

Log-transform del target TransformedTargetRegressor

La variable objetivo (salario_usd) se transforma con np.log1p antes del entrenamiento y se invierte con np.expm1 al predecir. Esto convierte el modelo en esencialmente aditivo en escala logarítmica: 

log(sal) = log(base) + log(m_sector) + log(m_empresa) + ... + log(1+bonus)
# → cada multiplicador es un término aditivo en log-space
# → el GBR aditivo puede aprender esto perfectamente con suficientes árboles

Sin log-transform, GBR intentaría minimizar errores absolutos — costoso en salarios altos (ejecutivos $12K–$18K). Con log-transform minimiza errores relativos, logrando MAE uniforme en todos los rangos salariales.

Backend — API FastAPI

Tecnología y endpoints

El backend está construido con FastAPI + uvicorn. Carga el modelo serializado (modelo_salario_pa.pkl) y la metadata (modelo_metadata.json) al arrancar.

EndpointMétodoDescripción
/healthGETEstado del modelo, R², MAE, versión
/opcionesGETTodas las opciones del formulario (áreas, sectores, etc.)
/predictPOSTRecibe perfil JSON → devuelve estimación + rango + tips

Contrato de la API — POST /predict

Request body:

{
  "area":             "Tecnología / IT",
  "sector":           "Multinacional",
  "tipo_empresa":     "Multinacional",
  "modalidad":        "Híbrido",
  "provincia":        "Panamá",
  "nivel_estudio":    "Maestría",
  "nivel_ingles":     "Avanzado",
  "años_experiencia": 8,
  "tiene_python":     1,
  "tiene_sql":        1,
  "tiene_powerbi":    0,
  "tiene_sap":        0,
  "tiene_excel_av":   0
}

Response:

{
  "salario_estimado": 3241,
  "rango_min":        2852,
  "rango_max":        3630,
  "moneda":           "USD",
  "periodicidad":     "mensual bruto",
  "tips": [
    "🌐 Mejorar inglés a Nativo/Bilingüe puede sumar otro 8%",
    "🏢 Las empresas locales grandes pagan hasta 18% menos que multinacionales"
  ],
  "modelo_version": "1.1-fase1"
}

El rango se calcula como ±12% del salario estimado, con piso Mitradel aplicado. Los tips se generan dinámicamente según las condiciones del perfil que más podrían mejorar el salario.

Validación de entrada Pydantic v2

FastAPI valida automáticamente el cuerpo del request usando el modelo Pydantic PerfilRequest. Si faltan campos o los tipos son incorrectos, devuelve HTTP 422 con detalle de los campos inválidos. Las herramientas tienen valor por defecto 0 (no requeridas).

Frontend — Aplicación Web

Tecnología y modo de operación

El frontend es un HTML estático puro sin dependencias de build (sin npm, sin bundler). Usa Google Fonts (Roboto + Roboto Mono) como única dependencia externa. Opera en dos modos:

ModoCondiciónDescripción
Demo local API_URL = "" La lógica de cálculo corre en JavaScript puro, espejando los multiplicadores del modelo Python. No requiere servidor.
En vivo API_URL = "https://..." Envía POST /predict al backend en Render. Si falla, cae automáticamente a modo demo.

Componentes de la UI

  • Ticker tape: barra superior animada con salarios promedio por área/cargo, datos reales del CSV
  • Header sticky: logo SP, badge de versión del modelo y R²
  • Formulario (panel izquierdo): 7 selectores + 1 slider de experiencia + 5 chips de herramientas. El botón se habilita solo cuando todos los campos están completos.
  • Panel resultado (panel derecho): número animado con easing cúbico, barra de rango min → estimado → max con animación CSS, cards de tips personalizados
  • Modo demo vs en vivo: fallback automático si el backend no responde
